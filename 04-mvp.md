# 4. MVP — Produto Mínimo Viável

## 4.1 O que é MVP?

MVP é a sigla de *Minimum Viable Product*, traduzida como **Produto Mínimo Viável**. É uma versão inicial de um produto, com o conjunto mínimo de recursos necessário para testar hipóteses importantes e aprender com usuários reais ou com o público-alvo.

O MVP não é simplesmente um produto malfeito ou uma versão cheia de defeitos. Ele deve ser suficientemente funcional para permitir uma avaliação útil da proposta de valor.

## 4.2 Para que serve?

Um MVP pode ajudar a:
- verificar se existe interesse na solução;
- testar hipóteses antes de investir muitos recursos;
- recolher feedback dos usuários;
- descobrir quais funcionalidades são realmente importantes;
- orientar as próximas decisões de desenvolvimento.

## 4.3 Exemplo prático: aplicativo de delivery

Imagine a ideia de desenvolver um aplicativo para pedidos de comida.

Uma primeira versão poderia permitir:
- visualizar os restaurantes ou produtos disponíveis;
- consultar detalhes e preços;
- montar um pedido;
- enviar o pedido ao estabelecimento por um canal definido.

Funcionalidades como programa de fidelidade, recomendações personalizadas e relatórios avançados poderiam ficar para etapas futuras, caso não sejam necessárias para testar a hipótese inicial.

O conjunto exato de recursos depende do público, do problema a ser validado e dos requisitos essenciais.

## 4.4 MVP não é o mesmo que protótipo

Um **protótipo** é uma representação ou simulação usada para explorar uma ideia, testar fluxos ou avaliar uma interface. Pode não funcionar como um produto real.

Um **MVP** é uma versão utilizável que permite testar hipóteses relevantes com evidências. Dependendo do objetivo, um MVP pode ser simples e até utilizar processos manuais nos bastidores, desde que entregue valor e permita aprender.

## 4.5 Ciclo de aprendizagem

Uma abordagem comum é:

1. **Construir:** desenvolver uma versão pequena para testar uma hipótese.
2. **Medir:** observar resultados, comportamento e feedback.
3. **Aprender:** analisar as evidências e decidir o que mudar.
4. **Iterar:** melhorar a solução, testar outra hipótese ou rever a ideia.

O objetivo é tomar decisões com base em evidências, não apenas em suposições.

## 4.6 Como definir um MVP

Antes de começar, responda:
- Qual problema queremos resolver?
- Quem enfrenta esse problema?
- Qual hipótese precisa ser testada primeiro?
- Qual é o menor conjunto de recursos que permite testá-la?
- Como saberemos se o teste funcionou?
- Que feedback ou métrica será observado?

Também é importante considerar privacidade, segurança, acessibilidade e requisitos legais pertinentes. “Mínimo” não significa ignorar esses cuidados.

## 4.7 Resumo

O MVP é uma estratégia para aprender sobre uma solução com investimento inicial controlado. Ele permite validar hipóteses, receber feedback e priorizar melhorias antes de ampliar o produto.
